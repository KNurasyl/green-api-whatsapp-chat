# GREEN-API Chat

Минимальный чат на React для отправки и получения текстовых сообщений WhatsApp через GREEN-API. Пользователь подключает свой инстанс, создаёт чат по номеру телефона и переписывается с собеседником.

Проект выполнен по [тестовому заданию](https://drive.google.com/file/d/1Ut39kkIs0QK-swnCsIPJc6pNqVIVGOD2/view). WhatsApp выбран как разрешённая в задании замена MAX.

[Открыть демо](https://green-api-whatsapp-chat-one.vercel.app/) · [Скриншоты и релиз](https://github.com/KNurasyl/green-api-whatsapp-chat/releases/tag/v0.3.2)

## Возможности

- Подключение своего инстанса через `apiUrl`, `idInstance` и `apiTokenInstance`.
- Проверка номера WhatsApp и создание личного чата.
- Отправка текста и получение ответов через HTTP API.
- Статусы отправки, доставки и прочтения, если они включены в настройках инстанса.
- Черновик для каждого чата, обработка ошибок и восстановление получения после обрыва связи.
- Адаптивный интерфейс для компьютера и телефона.

## Запуск

Нужны Node.js 24, npm и Git.

```sh
git clone https://github.com/KNurasyl/green-api-whatsapp-chat.git
cd green-api-whatsapp-chat
npm ci
npm run dev
```

Откройте адрес из терминала, обычно `http://127.0.0.1:5173`. Vite запускает интерфейс и серверный обработчик API; отдельный процесс сервера не нужен.

Для запуска собранной версии:

```sh
npm run build
npm start
```

Приложение будет доступно по адресу `http://127.0.0.1:3000`.

## Подключение WhatsApp

1. Откройте [кабинет GREEN-API](https://console.green-api.com/instanceList) и выберите WhatsApp-инстанс.
2. Привяжите WhatsApp по QR-коду. Дождитесь статуса «Авторизован».
3. Включите входящие уведомления `incomingWebhook` и уведомления состояния `stateWebhook`. Оставьте `webhookUrl` пустым, чтобы получать уведомления через HTTP API.
4. Для статусов сообщений включите `outgoingWebhook`, `outgoingAPIMessageWebhook` и `outgoingMessageWebhook`.
5. Скопируйте `apiUrl`, `idInstance` и `apiTokenInstance` из кабинета в форму подключения.
6. Нажмите «Новый чат», введите номер собеседника с кодом страны и откройте чат.

Enter отправляет сообщение, Shift + Enter добавляет строку. Ответ собеседника появляется в чате автоматически.

Приложение проверяет настройки инстанса при подключении, но не меняет их. Очередь одного инстанса должен читать один клиент: не запускайте параллельно несколько вкладок или другой клиент с `ReceiveNotification`.

## Переменные окружения

Форма подключения работает без `.env`. Для локального подключения без повторного ввода реквизитов скопируйте `.env.example` в `.env`, заполните три переменные GREEN-API и перезапустите приложение. На экране входа появится кнопка «Использовать локальный .env».

| Переменная              | Назначение                                                                   |
| ----------------------- | ---------------------------------------------------------------------------- |
| `GREEN_API_URL`         | `apiUrl` из кабинета GREEN-API                                               |
| `GREEN_API_INSTANCE_ID` | ID инстанса                                                                  |
| `GREEN_API_TOKEN`       | Токен инстанса                                                               |
| `SESSION_SECRET`        | Ключ шифрования сессии; обязателен на Vercel, не менее 32 случайных символов |
| `APP_ORIGIN`            | Полный origin собственного домена, например `https://chat.example.com`       |

Локально без `SESSION_SECRET` сервер создаёт временный ключ на время работы процесса. `.env` исключён из Git. Секреты не должны попадать в переменные `VITE_*`.

На публичном сервере подключение из `.env` отключено. Каждый посетитель вводит реквизиты своего инстанса.

## Архитектура

React, TypeScript, Vite, Zustand, TanStack Query, CSS Modules и `fetch`. Клиент построен по Feature-Sliced Design.

| Каталог        | Ответственность                                            |
| -------------- | ---------------------------------------------------------- |
| `src/app`      | Запуск приложения, провайдеры и общие стили                |
| `src/pages`    | Экран подключения и страница чата                          |
| `src/features` | Подключение, создание чата, отправка и получение сообщений |
| `src/entities` | Модели чатов, сообщений и сессии                           |
| `src/shared`   | HTTP-клиент, обработка ошибок и общие элементы интерфейса  |
| `server`       | Проверка запросов, сессии и обращения к GREEN-API          |
| `api`          | Входная функция Vercel                                     |
| `tests`        | Тесты моделей, запросов, React-сценариев и сервера         |

Zustand хранит чаты, черновики и текущую сессию. TanStack Query управляет запросами и их состояниями. React хранит локальное состояние форм. Серверный код не импортируется в клиент.

Данные проходят по цепочке: браузер → `/api` → GREEN-API. Сервер разрешает только необходимые методы и возвращает только используемые поля ответа.

Уведомления обрабатываются последовательно: `ReceiveNotification` → обновление чата → `DeleteNotification`. Идентификаторы `@c.us` и `@lid` связываются с одним локальным чатом. Повторные сообщения отсекаются по идентификатору.

## Сессия и сообщения

Реквизиты передаются серверу и хранятся в зашифрованной HttpOnly cookie через `iron-session`. На Vercel cookie имеет флаги `Secure` и `SameSite=Strict`. Дополнительный ключ запросов хранится только в памяти приложения. Токен не записывается в Web Storage или ключи кеша запросов; поле токена очищается после отправки формы.

Сессия действует один час. При выходе запросы отменяются, локальное состояние очищается и отправляется запрос удаления cookie. WhatsApp остаётся привязанным в GREEN-API. Централизованного отзыва ранее скопированной cookie нет; срок её действия ограничен.

Ответ `SendMessage` означает принятие запроса. Доставка и прочтение подтверждаются отдельными уведомлениями. При таймауте отправка не повторяется автоматически: текст сохраняется, а интерфейс предлагает проверить WhatsApp перед повторной попыткой.

## Проверки

```sh
npm run check
npm test
npm run build
```

`check` запускает Prettier, ESLint, проверку границ FSD и TypeScript. В версии 0.3.2 проходят 113 тестов: они проверяют чаты, aliases, дедупликацию, статусы, отправку, очередь уведомлений, отмену запросов и серверные сессии.

На публичном демо проверены живой вход, создание чата со своим номером, получение уведомлений, мобильная навигация с сохранением черновика и выход. Ранее отправка на свой номер подтверждалась статусом `sent`. Полный обмен с ответом другого WhatsApp-аккаунта и реальные статусы `delivered`/`read` не проверены: второго аккаунта для проверки не было.

Steiger сообщает четыре рекомендации о feature-слайсах, используемых одной страницей; нарушений границ слоёв нет. `npm audit --omit=dev` не выявил уязвимостей. Полный аудит отмечает уязвимость `braces` в цепочке зависимостей Steiger: [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm).

## Размещение на Vercel

1. Импортируйте репозиторий в Vercel с preset Vite.
2. Задайте `SESSION_SECRET` в окружениях, где будет работать приложение.
3. Для собственного домена задайте `APP_ORIGIN`.
4. Выполните деплой. Команда сборки, каталог `dist` и маршрут API уже заданы в `vercel.json`.

Ключ сессии можно создать локально:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Используйте основной [адрес демо](https://green-api-whatsapp-chat-one.vercel.app/). В текущей версии домены preview-веток не входят в список разрешённых адресов API.

## Ограничения

- Поддерживаются личные текстовые сообщения. Группы, файлы, звонки и история WhatsApp не загружаются.
- Чаты и черновики живут в текущей сессии и очищаются при перезагрузке страницы или выходе.
- При быстром повторном входе задержавшийся ответ на выход может завершить новое подключение; в таком случае потребуется подключиться ещё раз.
- Обмен зависит от авторизации и лимитов инстанса GREEN-API. Во время проверки очередь вернула `quotaExceeded`; приложение отображает это уведомление. Для проверки переписки нужен доступный лимит и отдельный собеседник.
